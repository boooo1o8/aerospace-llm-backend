# 接口对接约定 0.2.0

执行服务已实现，具体部署、格式、参数限制和验证入口见 [执行服务说明](execution-v0.2.md)。本文职责划分仍需与中台共同确认后冻结。

## 1. 职责与调用边界

自有前端对接中台提供的统一业务 API，中台调用后端执行服务和模型推理服务。服务鉴权密钥只由服务端持有。后端内部路径、服务器模型目录和 GPU 配置不作为前端的固定依赖。

| 前端页面需要的能力 | 中台负责 | 后端负责 |
|---|---|---|
| 上传资料和管理题目 | 题目字段、答案、审核与题库权限 | 文件保存、元信息、文件读取 |
| 选择训练题和测试题 | 划分规则、审核、数据版本归属 | 接收已整理的数据文件，校验格式和校验和 |
| 启动、排队、停止训练 | 业务任务创建、优先级和排队 | 接收已分配资源的执行请求，启动进程、取消、释放资源 |
| 查看训练状态和日志 | 向前端聚合展示 | 返回实际执行状态、进度、指标与日志游标 |
| 对话与批量答题 | 校验用户是否能使用模型和题库 | 实际模型推理，返回逐题原始回答 |
| 成绩对比和报告 | 单选、多选、填空评分及统计 | 提供模型版本、原始回答和可追溯运行记录 |
| 下载、导出模型 | 校验业务使用权限 | 再次执行资源授权校验并返回允许访问的产物 |

项目、操作者上下文不能单独作为授权凭据。执行服务已将它们与服务凭据允许列表绑定校验；中台实际用户角色、资源级业务授权与审计仍需进一步对齐。原生推理 API 的单个共享密钥尚未实现项目用户角色和资源权限。

## 2. 已可调用的推理接口

以 `inference.openapi.json` 为原生推理接口参考；具体以实际部署服务的 /openapi.json 为准。服务端基础地址为 `http://127.0.0.1:8000`。

| 方法与路径 | 状态 | 约定 |
|---|---|---|
| `GET /v1/models` | 已验证 | Bearer 鉴权，返回 OpenAI 风格模型列表 |
| `POST /v1/chat/completions` | 已验证 | JSON 对话请求，`stream=false` 返回完整响应 |
| `POST /v1/chat/completions`，`stream=true` | 已验证 | SSE，读取 `choices[].delta.content`，以 `[DONE]` 结束 |
| `GET /docs`、`GET /openapi.json` | 已验证 | 查看文档和导出定义 |
| `POST /v1/score/evaluation` | 原生定义存在，当前生成模型不支持 | 奖励模型打分用途，不是题库业务评分接口 |

当前只有一个部署模型。`model` 字段是接口标识，当前原生服务不提供多模型路由保证。调用方应先获取模型列表并使用返回的标识。

请求示例：

```json
{
  "model": "qwen2.5-1.5b-lora-demo",
  "messages": [{"role": "user", "content": "计算 17 加 25，简短回答。"}],
  "max_tokens": 64,
  "temperature": 0.1,
  "stream": false
}
```

响应读取 `choices[0].message.content`，token 数读取 `usage`。当前原生错误保持 FastAPI 的 `detail` 结构，不套用下节执行服务的错误结构。SSE 连接中断时，调用方不得假定服务端生成已取消或请求只执行过一次。

## 3. 后端执行接口

以 `execution.openapi.json` 为机器可读契约。12 个操作已实现，服务器基础地址为 `http://127.0.0.1:8010`。第一版开放单卡 LoRA、Alpaca 训练和 question_set_v1 批量问答；其他方法逐项验证后开放。

| 方法与路径 | 含义 |
|---|---|
| `GET /internal/v1/capabilities` | 查询已实现方法、模型能力和限制 |
| `POST /internal/v1/files` | 上传原始资料或整理后的数据文件 |
| `POST /internal/v1/dataset-versions` | 注册不可变数据版本，引用已上传的训练、评估文件 |
| `GET /internal/v1/dataset-versions/{dataset_version_id}` | 查询版本、样本数和校验信息 |
| `GET /internal/v1/models` | 查询受管理的模型目录 |
| `POST /internal/v1/training-runs` | 创建一次训练执行，引用模型 ID 和数据版本 ID |
| `GET /internal/v1/training-runs/{run_id}` | 查询训练实际状态、指标与产物引用 |
| `POST /internal/v1/training-runs/{run_id}/cancel` | 请求取消，状态到达 cancelled 后才表示资源已释放 |
| `GET /internal/v1/training-runs/{run_id}/logs` | 按不透明游标增量获取日志 |
| `POST /internal/v1/prediction-runs` | 创建模型批量答题执行 |
| `GET /internal/v1/prediction-runs/{run_id}` | 查询批量答题状态和结果产物 |
| `GET /internal/v1/artifacts/{artifact_id}/content` | 按授权下载产物 |

### 训练执行状态

`accepted` 表示后端已持久接收请求；中台负责尚未下发的业务排队。后端准备完毕并开始运行后进入 `running`。成功结束为 `succeeded`，异常结束为 `failed`。

取消过程为 `cancel_requested`，在相关进程退出、GPU 占用释放并完成记录后进入 `cancelled`。`succeeded`、`failed`、`cancelled` 为终态，不允许倒退。相同执行 ID 的重试不复用旧运行目录；中台创建新执行请求并引用原业务任务 ID。

`phase`、`current_step`、`total_steps`、`epoch` 和 `latest_loss` 均按实际数据返回，未知时为 null。NaN 和 Infinity 不作为合法 JSON 数字传递；出现非有限指标时返回 null，并记录诊断原因，最终状态按执行结果判定。

### 模型、数据与产物引用

- 前端、中台使用稳定的 `model_id`、`dataset_version_id`、`artifact_id`。
- 模型物理路径、启动命令、环境和实际文件路径由后端解析。
- 训练文件格式、校验和和引用的数据版本固定保存。数据版本注册之后不可原地替换。
- 题目划分是否符合业务要求由中台审核；后端执行结构、引用和内容校验和检查。
- 训练请求采用结构化、允许列表内的参数，不接收任意 shell、Python 或不受约束的额外启动参数。
- GPU 资源分配由中台调度结果或约定的资源管理模块给出；后端还需校验资源可用性和账号范围。

### 日志与批量答题

第一版按游标查询日志和任务状态，保留接入事件推送的空间。日志要过滤访问密钥和敏感字段。游标由服务端产生，客户端不得将其当作行号或文件偏移自行构造。

批量答题结果保留稳定的 `question_id`、原始模型输出、解析状态、用量及单题错误信息。后端不在此结果中给出总分或题型得分，这部分由中台按统一规则计算。测试题与评分版本引用由中台保存。

## 4. 执行服务通用协议

- JSON 使用 UTF-8；时间戳采用带时区的 RFC 3339 字符串。
- 服务端返回 `X-Request-ID`，与错误响应中的 `request_id` 一致。
- 创建训练和批量答题时要求 `Idempotency-Key`。同一服务、项目、操作者、执行类型内，相同 key 和请求体返回同一执行 ID；相同 key 对应不同请求体返回 409。当前记录不自动清理，至少保留 24 小时。
- 创建执行返回 202 及状态查询地址；校验失败或无权限不得启动进程。
- 执行服务错误结构为 `{ "error": { "code": "...", "message": "...", "request_id": "...", "details": {} } }`。
- 400：请求语义错误；401：未认证；403：未授权；404：资源不存在或对调用方不可见；409：状态或幂等冲突；422：字段校验失败；429：并发或限流；503：执行资源不可用。
- 下载、状态、日志和产物读取均需授权校验。实现业务后端前，不能以当前演示密钥代替完整权限方案。

## 5. 联调与版本维护

1. 先核对接口归属、ID 格式、题目字段、评分规则，以及中台传递授权上下文的方式。
2. 第一版已实现模型目录、数据版本、LoRA 任务创建、状态、日志、取消和产物引用，可开始中台联调。
3. 批量答题已实现并用新训练适配器验证，评分与报告仍由中台完成。
4. 能力接口只声明实际已实现的方法。QLoRA、全量微调等方法逐项验证后再开放。
5. 新增可选字段通常可保持 v1；删除字段、改变含义或改变状态流程需要迁移说明。进入正式维护阶段后，破坏性变更采用新主版本。
6. 每次接口变更更新 CHANGELOG、示例、OpenAPI，并完成对应黑盒联调检查。服务已部署不代表自有前端或中台已经完成接入。

## 6. 原生推理服务

普通聊天和流式聊天属于 LLaMAFactory 原生 API，需要另外启动。它与本项目执行服务的凭据、端口及模型生命周期独立，不能认为部署本后端就自动启动了原生聊天服务。

`contracts/v1/inference.openapi.json` 是历史原生接口的参考定义，不保证与其他版本的 LLaMAFactory 完全相同。运行和验证方法见 README 与 validation.md。
